# Publication checklist

- [ ] Run `python run_tests.py` locally (record Python version and skipped tests).
- [ ] Run `python run.py walkthrough` locally and verify the lifecycle.
- [ ] Review `git status --short` and `git diff --cached --stat` before commit.
- [ ] Confirm neither WGU archive, ZIP, private data nor `.venv` / `.state` was staged.
- [ ] Inspect source and history for secrets (a successful scan alone is not a guarantee).
- [ ] Choose whether to add a license; the default without a license is all rights reserved.
- [ ] Create a **new** public GitHub repository named `network-reliability-lab`.
- [ ] Push only verified original portfolio source, tests, and documentation.
- [ ] Inspect the public repository as a recruiter: source browseable, commands easy to find, no dead links.
- [ ] Verify GitHub Actions success on supported versions before adding a CI badge or claiming it passed.
- [ ] Link the published repository from the GitHub profile README and resume after verification.

## Integrity note

Do not manufacture old commits, false contributors, deploy screenshots, production claims, or passing CI evidence. A small authentic history that grows with real changes is stronger than cosmetic activity.
